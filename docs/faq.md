# FAQ

### Does this replace a SOC analyst?

No, and it is not built to. It removes the mechanical part of reading an alert
and returns a structured first pass. Every judgement stays with the analyst. The
workflow has no way to act on anything.

### Why a local model instead of a hosted API?

Security telemetry contains internal hostnames, usernames, private addressing
and live incident detail. Sending it to a hosted API exports it to a third
party. Ollama on your own infrastructure keeps it inside the same trust boundary
as the SIEM that produced it.

### Can I point it at a hosted API anyway?

You can — change `OLLAMA_BASE_URL` and adapt the request body. Understand that
this changes the data protection posture of the whole system with a one-line
edit and no visible warning. Get it approved first.

### Which model should I use?

The workflow ships with `qwen3:14b`, which is what it was built and tested
against. Two constraints when substituting: the context window must comfortably
exceed the largest prompt (~31 KB for Palo Alto) plus the event, or the
output-format instructions at the end get truncated; and smaller models drift
back into Markdown despite being told not to. Re-run the six-case test set.

### Why does the assistant sometimes not reply?

Three possibilities. The loop guard dropped the message (correct, for bot
messages). The input classified as `ip`, `hash` or `linux`, whose Switch outputs
are not connected — a known defect. Or inference failed and there is no error
branch. See
[`../workflows/n8n/ai-soc-assistant/troubleshooting.md`](../workflows/n8n/ai-soc-assistant/troubleshooting.md).

### Why are three Switch outputs unconnected?

Because that is what the workflow does today, and this repository documents what
runs. The classifier assigns `ip`, `hash` and `linux`, the Switch has outputs
for them, and nothing is wired downstream. It is roadmap item 1. The cheapest
interim fix is a Switch fallback into the general prompt.

### Does it enrich indicators with VirusTotal or AbuseIPDB?

No. There is no enrichment node in the workflow. Where the prompts mention
"any supplied enrichment", nothing currently supplies it. It is planned.

### How is the risk score calculated?

It is not. `Verdict`, `Severity`, `Overall Risk` and `Confidence` are text
generated by the language model. There is no scoring formula in the workflow.
A deterministic score computed outside the model is roadmap item 3.

### Why do Severity and Overall Risk differ?

They measure different things. Severity is the immediate operational impact of
the observed event; Overall Risk is the likelihood it represents a genuine
incident once you account for what actually happened. Blocked malware on an
endpoint is high severity — a control failed — and medium overall risk, because
it was quarantined with no observed execution.

### Can I trust the Confidence field?

Not as a measurement. It is the model's self-report, not a calibrated
probability. A model can say `Confidence: High` on a fabricated conclusion.

### Why does it say "Requires Investigation" so often?

Because that is the mandated answer when the evidence cannot distinguish between
a benign and a malicious explanation. Most single alerts, viewed without
environmental context, genuinely cannot. A confident verdict on thin evidence
would be a guess presented as an assessment.

### Why no Markdown in the output?

Slack renders Markdown inconsistently inside security text full of backslashes,
paths and special characters. Plain text with `•` bullets is predictable.

### Can it block an IP or isolate a host?

No. There is no node in this workflow capable of changing the state of any
security control. This is structural, not a setting. See
[`human-in-the-loop.md`](human-in-the-loop.md).

### Is the webhook secure?

No. It has no authentication and does not verify Slack's request signature.
Anyone with the URL can use it. Mitigate with a reverse proxy that verifies
`X-Slack-Signature`, source restrictions and rate limiting. This is the most
important open item — see
[`security-model.md`](security-model.md#unauthenticated-webhook).

### Can log content manipulate the model?

Yes, in principle. Event text reaches the model as an unescaped user message,
and log fields are attacker-influenceable. What limits the harm is that the
model has no tools and cannot act — the worst case is a misleading message a
human reads. See [`threat-model.md`](threat-model.md#t4--prompt-injection-via-log-content).

### Did this project use Shuffle?

No. Shuffle was never deployed and no Shuffle workflow was built. Everything
implemented here runs on n8n + Ollama + Slack.

The `workflows/shuffle/planned/` directory contains forward-looking design notes
for a SOAR layer this project does not currently have. They are labelled
`Not built` throughout. Publishing a fabricated export to fill the directory
would misrepresent the project.

### Why is `=event_type` spelled with an equals sign?

Because it is, in the live workflow. In n8n's Set node the `=` prefix marks a
*value* as an expression; here it was also typed into the field-name box, so the
item carries a key literally named `=event_type`. Nothing reads it, so nothing
breaks. It is preserved because this repository ships what actually runs.

### Can I use this with a SIEM other than Wazuh?

Partly. The classifier detects FortiGate, Palo Alto, F5 and Trend Micro CEF from
text patterns as well as from Wazuh document structure, so raw syslog often
routes correctly. The `wazuh_json` prompt is Wazuh-specific. Adding a source
means a new classifier branch, a new Switch output, a new prompt node, and a new
test case.

### Is my data sent anywhere I do not control?

Slack has it already, because that is where the analyst pasted it. Beyond that,
no — provided `OLLAMA_BASE_URL` points at your own host. Note that n8n execution
history retains the full text of everything analysed until pruned.

### Why does the repository document its own defects so prominently?

Because a reader cannot otherwise tell the difference between a repository with
no defects and one that hides them. If the limitations sections are wrong,
that is a bug worth reporting.
